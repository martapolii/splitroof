# Firestore Data Model

This document defines the official Firestore collection names, document structures, and field names used by SplitRoof.

**Important:** Use these exact names in the API, frontend, and tests. Do not introduce new collection or field names without updating this document.

## 1. Overview

Firestore is the database used by SplitRoof.

| Term | Meaning |
|---|---|
| Collection | A group of records, similar to a database table |
| Document | One record inside a collection |
| Field | A value stored inside a document |

SplitRoof has **five collections**:

| Collection | Description |
|---|---|
| `users` | One person with an account |
| `households` | One group of roommates sharing costs |
| `expenses` | One shared purchase |
| `settlements` | One payment from one roommate to another |
| `budgets` | One spending limit for a category in a month |

## 2. Global Data Rules

These rules apply to every collection.

### Authentication

- Passwords are **not stored in Firestore**. Firebase Authentication manages passwords.
- The `users` document ID must be the person's Firebase Auth UID.
- Do not generate a random ID for user documents.

### Household Membership

- A person can belong to at most one household.
- `currentHouseholdId` stores the household document ID.
- If the person has not joined a household, `currentHouseholdId` must be `null`.

### Balances

- Do not store balances in Firestore.
- Who owes whom must be calculated from expenses and settlements.

### Money and Currency

SplitRoof uses Canadian dollars (CAD).

**All monetary values must be stored as integer cents.**

| Amount | Stored Value |
|---|---:|
| $5.00 | `500` |
| $12.50 | `1250` |
| $300.00 | `30000` |

Rules:

- Expenses and settlements must be at least `1` cent.
- Budget limits can be `0` or greater.
- Each person's share must be stored in cents.
- The sum of all shares must equal the expense's `amountCents`.

**Example: Equal split of $10.00 between three people**

| Member | Share |
|---|---:|
| Person 1 | 334 cents |
| Person 2 | 333 cents |
| Person 3 | 333 cents |
| **Total** | **1,000 cents** |

Any leftover cents go to the next person in `memberIds` order.

### Dates

Dates are stored as plain text, not timestamps.

| Field | Format | Example |
|---|---|---|
| Expense date | `YYYY-MM-DD` | `2026-11-13` |
| Settlement date | `YYYY-MM-DD` | `2026-11-13` |
| Budget month | `YYYY-MM` | `2026-11` |

This prevents time zone differences from changing the calendar day selected by the user.

### Categories

Use these exact category names. They must match `frontend/src/categories.js`.

`Rent`, `Utilities`, `Groceries`, `Household`, `Entertainment`, `Other`

## 3. Users

**Purpose:** Stores one person's account information.

**Document ID:** Firebase Authentication UID.

### Example Document

```json
{
  "email": "alex@example.com",
  "username": "Alex",
  "currentHouseholdId": "house_abc123"
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `email` | string | User's email address, stored in lowercase |
| `username` | string | Display name shown to roommates |
| `currentHouseholdId` | string or null | Household document ID, or `null` if the user has not joined one |

### Validation Rules

- Emails must be saved in lowercase.
- Usernames must be unique, ignoring capitalization.
- Preserve the capitalization entered by the user.
- `currentHouseholdId` must reference a valid household or be `null`.

## 4. Households

**Purpose:** Stores a group of roommates sharing expenses.

**Document ID:** Automatically generated by Firestore.

### Example Document

```json
{
  "name": "Apartment 4B",
  "adminId": "uid_alex",
  "memberIds": ["uid_alex", "uid_sam"],
  "inviteCode": "K7NQ2MHW"
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `name` | string | Household name |
| `adminId` | string | UID of the Household Admin |
| `memberIds` | array | UIDs of all household members, including the admin |
| `inviteCode` | string | Unique code used to join the household |

### Validation Rules

- A household must have between **1 and 6 members**.
- The API must reject a seventh member.
- The admin must also appear in `memberIds`.
- Invite codes must be unique.
- Invite codes must contain exactly 8 characters.
- Allowed characters: `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`.

## 5. Expenses

**Purpose:** Stores a purchase shared between household members.

**Document ID:** Automatically generated by Firestore.

### Example Document

```json
{
  "householdId": "house_abc123",
  "amountCents": 1000,
  "description": "Groceries",
  "date": "2026-11-13",
  "payerId": "uid_alex",
  "category": "Groceries",
  "split": "equal",
  "shares": [
    { "userId": "uid_alex", "amountCents": 500 },
    { "userId": "uid_sam", "amountCents": 500 }
  ]
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `householdId` | string | Household document ID |
| `amountCents` | number | Total purchase amount in cents |
| `description` | string | Short description of the purchase |
| `date` | string | Purchase date (`YYYY-MM-DD`) |
| `payerId` | string | UID of the person who paid |
| `category` | string | One of the six approved categories |
| `split` | string | `equal` or `custom` |
| `shares` | array | Individual member shares |

### Share Structure

Each object inside `shares` contains:

| Field | Type | Description |
|---|---|---|
| `userId` | string | UID of the person responsible for the share |
| `amountCents` | number | Their portion of the expense in cents |

### Validation Rules

- `amountCents` must be greater than `0`.
- `payerId` must belong to the household.
- `split` must be `equal` or `custom`.
- Shares must add up to the total `amountCents`.
- Individual shares can be `0`.
- The payer can also have a share.
- Historical expenses must remain when a member leaves the household.

## 6. Settlements

**Purpose:** Records a payment from one roommate to another.

**Document ID:** Automatically generated by Firestore.

**Note:** Settlements are records only. The app does not transfer real money.

### Example Document

```json
{
  "householdId": "house_abc123",
  "date": "2026-11-13",
  "payerId": "uid_sam",
  "receiverId": "uid_alex",
  "amountCents": 500
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `householdId` | string | Household document ID |
| `date` | string | Payment date (`YYYY-MM-DD`) |
| `payerId` | string | UID of the person sending the payment |
| `receiverId` | string | UID of the person receiving the payment |
| `amountCents` | number | Payment amount in cents |

### Validation Rules

- `amountCents` must be greater than `0`.
- `payerId` and `receiverId` must be different people.
- Both users must belong to the household.

**Example:** Sam pays Alex $5.00. The settlement stores `500` cents.

## 7. Budgets

**Purpose:** Stores a spending limit for one household, category, and month.

**Document ID:** Automatically generated by Firestore.

### Example Document

```json
{
  "householdId": "house_abc123",
  "category": "Groceries",
  "month": "2026-11",
  "limitCents": 30000
}
```

### Fields

| Field | Type | Description |
|---|---|---|
| `householdId` | string | Household document ID |
| `category` | string | One of the six approved categories |
| `month` | string | Budget month (`YYYY-MM`) |
| `limitCents` | number | Spending limit in integer cents |

### Validation Rules

- `limitCents` must be `0` or greater.
- `30000` represents $300.00.
- Only one budget is allowed per household, category, and month.
- The API must reject duplicate budgets for the same combination.

## Final Notes

- Always use the exact collection and field names defined in this document.
- All monetary values must use integer cents.
- All dates must follow the specified string formats.
- The API is responsible for enforcing validation rules that Firestore does not automatically enforce.
- Update this document whenever the agreed data model changes.
